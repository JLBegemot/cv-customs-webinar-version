# Профили ручек cv-customs (webinar edition)

Транспорт один — REST поверх FastAPI, профиль один — `http`. Профиль ручки
объявляется в шапке плана и в поле `profile` каждого кейса в `cases.yaml`.

| Профиль | Признак | Примеры в репозитории |
|---|---|---|
| `http` | обычная синхронная ручка | `tests/api/test_user_account.py`, `tests/api/test_resume_upload.py` |

---

## `http` — обычная ручка

**Шаг 2 (обвязка).** `build_client()` для боевого приложения или
`build_client(routers=[module.router])` для одного роутера. Заголовки — `auth_headers(user_id)`.

**Шаг 6 (категории кейсов), обязательный минимум:**

| Категория | Ожидание |
|---|---|
| Happy path | 2xx + ассерты на **значения** полей ответа, не на их наличие |
| Отсутствует обязательное поле | 422 от Pydantic |
| Невалидный тип / формат поля | 422 |
| Нет токена | 401 |
| Чужой объект | **404, не 403** (AUTH-002) |
| Невалидный UUID в пути | 404, не 422 (AUTH-003) |
| Побочный эффект | проверяется у источника: строка в БД, письмо в `email_client.sent`, блоб в fake-S3 |

**Ловушка.** Ветка хендлера легко подменяется валидацией схемы: тест на «нет обязательного
поля» может уйти в 422 на схеме и не дойти до ветки, которую проверяет (ASSERT-005).
Если проверяется именно ветка хендлера — тело запроса должно проходить схему.

### Ручки с файлами (`/api/v1/resumes/*`)

Единственная специфика поверх `http` — блоб-стор:

- S3 подменяется in-memory-двойником и передаётся в стенд:
  `build_client(routers=[resumes.router], s3=fake_s3)` — образец `FakeS3`
  в `tests/api/test_resume_upload.py`. Настоящий MinIO в тестах не поднимается.
- `s3=None` (умолчание стенда) — это ветка «хранилища нет»: upload и download
  обязаны отвечать **503**, а не 500 и не «тихо без блоба».
- Валидация файла серверная: формат — по magic-байтам (`utils/mime.sniff_mime`),
  размер — `RESUME_UPLOAD_MAX_BYTES`. Клиентские `filename`/`Content-Type`
  не влияют на решение — кейс «текстовый файл с именем cv.pdf» обязателен.
- Побочный эффект upload'а проверяется в двух местах: строка в БД **и** блоб
  под ключом `resumes/{id}/original.{ext}` в fake-S3 (ASSERT-004).
- Типизированные коды ошибок: `UPLOAD_UNSUPPORTED_FORMAT` (422),
  `UPLOAD_TOO_LARGE` (413), `UPLOAD_EMPTY` (422) — ассерт на `detail.code`,
  не только на статус.
