# Добавить API изменения данных пользователя: email и отметки согласий

## Контекст

Профиль пользователя сейчас read-only: `GET /api/user/me` отдаёт `email`,
`consent_given_at`, `cross_border_consent_at`, но поменять их нельзя. Email —
идентификатор входа (уникальный, логин ищет его case-insensitive через
`get_user_by_email_ci`), почтовой верификации в webinar-редакции нет — смена
должна применяться сразу. Отметки согласий — таймстемпы, которые сервер ставит
сам; отзыв основного согласия по 152-ФЗ уже реализован отдельной ручкой
`POST /api/user/revoke-consent` и влечёт удаление аккаунта — эта семантика не
должна дублироваться или обходиться новой ручкой.

Затрагиваемый код:

- `backend/src/cv_customs/api/user.py` — новый хендлер `PATCH /api/user/me`
- `backend/src/cv_customs/db/repositories.py` — функции обновления email и согласий
- `docs/openapi.json` — перегенерировать снапшот

Миграция не нужна: все поля уже есть в `users`.

## Задача

Добавить `PATCH /api/user/me` — частичное обновление профиля: смена email и
выдача/отзыв согласий. Все ошибки — типизированные, изменения — с записью в
`audit_log`, ответ — актуальный `UserMeResponse`.

## Требования

1. **Частичность.** Тело — Pydantic-схема, все поля опциональны:
   `email`, `consent`, `cross_border_consent`.
   Непереданное поле не трогается. Тело без единого значимого поля — `422`,
   `{"code": "NOTHING_TO_UPDATE"}`.
2. **Смена email.** Подтверждение паролем не требуется — достаточно передать
   новый адрес.
   - `email` валидируется как `EmailStr`.
   - Занятость проверяется case-insensitive (`get_user_by_email_ci`). Занят
     другим пользователем — `409`, `{"code": "EMAIL_TAKEN"}`. Ответ не должен
     различать «занят» и «занят, но deleted» — оракула существования нет,
     код один.
   - Новый email равен текущему (с точностью до регистра) — no-op, `200`.
   - Применяется сразу: вход по старому email после смены — `401`, по новому —
     успех. Почтового подтверждения нет by design.
3. **Согласия.** Клиент передаёт булевы `consent` / `cross_border_consent`,
   таймстемпы ставит сервер:
   - `true` при пустой отметке — проставить `now(timezone.utc)`.
   - `true` при уже стоящей отметке — no-op, исходный таймстемп сохраняется
     (идемпотентность).
   - `cross_border_consent: false` — очистить `cross_border_consent_at`
     (разрешено: сужает обработку, аккаунт не трогает).
   - `consent: false` — **отказ**: `422`, `{"code": "CONSENT_REVOKE_FORBIDDEN"}`
     с подсказкой использовать `POST /api/user/revoke-consent`. Отзыв основного
     согласия равен удалению аккаунта и не должен случаться «мимоходом» через
     PATCH.
